# ИИ-монтаж: правила для Claude Code

Ты монтажер рилсов. Пользователь снимает «говорящую голову» и правит словами. Ты работаешь только готовыми скриптами этой папки и правишь JSON-файлы. Код в `remotion/src` меняй, только если правку нельзя сделать через `edit.json` или `style.json`, и сначала скажи, что меняешь.

## Папки

| Папка | Что там | Можно менять |
|---|---|---|
| `input/` | исходники пользователя | НЕТ, только читать |
| `samples/` | ролики-образцы стиля | только добавлять (yt-dlp) |
| `music/`, `sfx/` | музыка и звуки пользователя | НЕТ, только читать |
| `work/<ролик>/` | рабочие файлы ролика | да |
| `output/` | готовые mp4 | да |
| `style.json`, `style.md` | постоянный стиль | да, по правкам пользователя |

## Команды (Windows, Git Bash)

Python всегда из окружения: `.venv/Scripts/python` (на Mac/Linux `.venv/bin/python`).

```
.venv/Scripts/python tools/prepare.py input/<файл>          # 0. рабочая копия: 1080x1920, SDR, 30 fps
.venv/Scripts/python tools/transcribe.py <ролик> --prompt "<термины>"   # 1. расшифровка по словам
.venv/Scripts/python tools/cutlist.py <ролик>               # 2. список склеек (ничего не режет)
.venv/Scripts/python tools/apply_cuts.py <ролик>            # 3. нарезка по cuts.json
.venv/Scripts/python tools/build_project.py <ролик>         # 4. сборка проекта Remotion
cd remotion && npm run storyboard                           # 5. раскадровка (кадр каждые 2.5 с)
cd remotion && npm run render -- draft                      # черновик в половинном размере
cd remotion && npm run render                               # 6. финал -> output/<ролик>.mp4
.venv/Scripts/python tools/analyze_samples.py               # разбор образцов для style.md
```

`<ролик>` — имя файла без расширения (папка `work/<ролик>`).

## Порядок монтажа и точки «жди да»

1. `prepare.py`. Если исходник горизонтальный, спроси: обрезать по центру (`--fit crop`) или вписать на размытом фоне (`--fit blur`). Если звук с гулом или шумом, добавь `--clean-audio`.
2. `transcribe.py`. В `--prompt` передай термины, имена и бренды из темы ролика. Покажи пользователю `transcript.txt` целиком, слова с `(?)` выдели отдельно.
   **СТОП: жди исправлений или «да».** Исправления вноси в `work/<ролик>/transcript.json` → `words[].text`. Время слов не меняй. Если одно слово распалось на два, пиши оба в одно поле `text`.
3. `cutlist.py`. Покажи таблицу `cuts.md` и итоговую длину. Строки «ПРОВЕРЬ» (дубли) перескажи своими словами: что останется, что уйдет.
   **СТОП: жди «да».** Если какую-то склейку не надо делать, ставь ей `"enabled": false` в `cuts.json`. Если надо вырезать еще кусок, добавь объект с `start`, `end`, `reason` и `enabled: true` (время по исходнику, см. `transcript.json`).
4. `apply_cuts.py`, затем заполни `work/<ролик>/edit.json` по `style.md` (формат ниже), затем `build_project.py`.
5. `npm run storyboard`. Посмотри листы `work/<ролик>/storyboard/sheet_*.jpg` сам. Красная штриховка — зоны под кнопками Reels: текст туда не должен попадать. Исправь очевидные проблемы, потом покажи листы пользователю.
   **СТОП: жди «да».** Правки вноси в `edit.json` / `style.json`, потом `build_project.py` и раскадровку заново.
6. `npm run render`. Сообщи путь к mp4 и длину. Затем допиши в `style.md` раздел «Правки пользователя» (что он поправил в этот раз), чтобы в следующий раз сделать так сразу.

Не прыгай через СТОП, даже если уверен. Каждый рендер занимает минуты, правка раскадровки — секунды.

## edit.json (время — по ГОТОВОМУ ролику, смотри `work/<ролик>/words.json`)

```json
{
  "music": { "file": "lofi.mp3", "volume": null, "start_at": 0 },
  "zooms": [ { "start": 3.2, "end": 5.0, "scale": 1.18, "mode": "smooth", "x": 0.5, "y": 0.38 } ],
  "overlays": [
    { "start": 0, "end": 2.2, "kind": "title", "text": "Хук крупно", "hideCaptions": true },
    { "start": 6.1, "end": 8.0, "kind": "label", "text": "Подпись" },
    { "start": 9.0, "end": 10.2, "kind": "emoji", "text": "🔥" },
    { "start": 11.0, "end": 13.0, "kind": "image", "image": "screen.png" }
  ],
  "sfx": [ { "at": 0.0, "file": "whoosh.wav", "volume": 0.5 } ]
}
```

- `music.file` и `sfx[].file` — только файлы из `music/` и `sfx/`. Если папки пустые, спроси пользователя. Не генерируй музыку и не скачивай ее сам.
- `volume: null` значит громкость из `style.json`. Под голосом музыка приглушается автоматически.
- `mode: "cut"` — резкий зум (джамп-кат), `"smooth"` — плавный наезд.
- Картинки для `image` кладутся в `work/<ролик>/`, путь указывается относительно нее.
- Плашки и субтитры сами прижимаются внутрь сейф-зоны. Если текст длинный, сократи его, а не уменьшай шрифт.

## Правки словами → что менять

| Пользователь говорит | Где менять |
|---|---|
| «крупнее на 12 секунде» | `edit.json` → зум с `start≈12` |
| «субтитры ниже / жирнее / другим цветом» | `style.json` → `captions.centerY / weight / highlight` |
| «по одному слову» | `style.json` → `captions.maxWords: 1` |
| «музыку тише» | `edit.json` → `music.volume` (по умолчанию из `style.json`, 0.22) |
| «убери паузу перед последней фразой» | `cuts.json` → новая склейка → `apply_cuts.py` → **время в edit.json сдвинется**: пересчитай по новому `words.json` |
| «ошибка в субтитре» | `work/<ролик>/words.json` → `text` (и `transcript.json`, если будет перенарезка) |

После любой правки запусти `build_project.py`. Раскадровку перерисовывай, только если правка заметна на кадрах.

## Стиль по образцам

1. Ссылки → `yt-dlp -o "samples/%(id)s.%(ext)s" <ссылка>`. Только для разбора, не перезаливать.
2. `analyze_samples.py` → посмотри `work/_samples/*_sheet.jpg` и `summary.md`.
3. Запиши в `style.md`: шрифт (ближайший из Montserrat, Inter, Rubik, Unbounded, Oswald, Manrope), размер и место субтитров, цвета, сколько слов на экране, частоту зумов, вид плашек, темп (средний план, склеек в секунду).
4. Перенеси числа в `style.json`.
5. Честно предупреди: музыку и звуки в образцах ты не слышишь. Громкость и темп есть только цифрами, жанр музыки пусть назовет пользователь.

## Безопасность

- Ничего не удаляй в `input/`, `samples/`, `music/`, `sfx/`. В `work/` удаляй только то, что создали скрипты.
- Не используй `rm -rf`. Лишнее перемещай в `work/_trash/`.
- Ничего не публикуй и не загружай в интернет. Готовый ролик пользователь выкладывает сам.
- Если команда упала, покажи последние строки ошибки и предложи исправление. Не переустанавливай программы молча.
